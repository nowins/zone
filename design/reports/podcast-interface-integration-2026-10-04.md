# 播客页面整合与客户端验收报告

日期：2026-10-04。范围：发现／搜索的信息层级、资料库管理、一键本机备份、播客偏好与应用全局设置的整合。

## 复核发现与处理

此前功能检查覆盖了数据与操作，但页面组织仍存在问题。本轮先捕获正式客户端的实际界面，再根据现有 Zune 排版、文字导航、按钮和开关重新组织功能。

| 实际流程 | 复核发现 | 本轮处理 |
| --- | --- | --- |
| 1. 进入发现并筛选榜单 | 应用导航之后重复大标题、分区、搜索、主题、分类，结果被推到下方；主题与真实分类重叠；系统复选框突兀 | 根页面使用一行文字分区，搜索同排；移除重复大标题与主题行，真实分类直接选择，较多分类可横向浏览；未关注筛选使用可按下文字按钮 |
| 2. 搜索与手动关注 | 搜索辅助入口持续挤占内容区域 | 历史建议仅在搜索聚焦时展示；RSS 从辅助入口打开共享对话框，成功关注后关闭并进入节目 |
| 3. 进入资料库管理 | 三块内容横向空置、动作等权；默认设置额外占一行 | 左侧标题与范围、右侧状态与动作；按备份、迁移、同步排列；主要备份按钮与文字辅助动作区分 |
| 4. 创建备份与恢复 | 普通备份每次要求选择路径，未利用 Zone 数据目录 | 一键备份写入本机工作目录，显示最近备份；音频为显式可选项；导出到其他位置收进辅助入口；恢复选择器默认打开本机备份目录，预览后再确认 |
| 5. 修改默认播客偏好 | 应用已有设置入口，播客另开默认设置浮层；内容与操作拥挤 | 默认偏好放入全局设置的播客分类，与音乐、常规设置并列；播放和下载分开；高级时间间隔默认收起；采用现有开关，明确保存；切换分类保留草稿 |
| 6. 覆盖单个节目偏好 | 设置继承与覆盖难读，小窗口操作行接近播放器 | 节目页保留本节目设置；沿用默认时显示实际生效值；纵向条目、独立滚动内容、常驻取消／保存行 |

## 实现与边界

发现页复用 `Cover`、文字导航与主题焦点色，RSS 复用 `Dialog`／`Presence`；搜索输入法组合与历史键盘行为继续由同一个搜索组件处理。资料库管理和设置均沿用已有 `Button`、`MetroLoader` 与开关。

默认备份目录由 Rust 根据 `zone.sqlite` 所在目录确定，为其中的 `podcast-backups/`，不是项目 checkout 或音乐目录。前端只提交播客偏好与是否包含音频，不提交内部路径。每次创建独立清单；复用已有音频完整性校验、路径守卫与事务恢复流程。旧快照和原下载音频保留，失败只清理当前操作创建的文件。目录读取、创建、打开拒绝非普通目录及目录链接。导出到其他位置仍经过原生保存对话框，恢复仍先展示数量与音频摘要再合并。

全局设置仅保存明确提交的播客草稿；保存失败保留编辑值与错误提示。音乐资料库、歌词和常规设置分别位于相应分类，节目级偏好继续与默认偏好共享编辑实现。应用权限与网络／媒体协议访问范围没有扩大。

第一轮原生人工验收使用 `.tmp/podcast-client/2026-10-04T04-49-18.790Z-51432/` 的限时完整客户端，直接操作 Windows 原生选择器和实际 WebView。

- 全局设置的音乐／播客／常规分类内容独立；鼠标开启语音均衡，实际 Tab 将焦点移到静音开关，空格切换；离开播客分类后返回仍保留两项修改与未保存状态，保存成功后显示明确反馈。

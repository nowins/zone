# 性能观察与对照

先测量，再对明确热点做局部修改。性能结果按运行环境、数据规模和测量边界解释，不把单测进程、浏览器组件或两首歌的 CI 结果概括成整个播放器性能；不通过关闭正在播放动效、光焰或艺术家呈现来取得成绩。

## 可重复入口

在项目根执行，结果与生成夹具写入被忽略的 `.tmp/perf/`。运行期间避免并行构建或其他基准；记录正常后台负载无法完全控制的限制。不清空操作系统磁盘缓存、不更改设备、系统音量、电源计划或用户资料库。

```powershell
npm run perf:library -- before
npm run perf:search -- origin/main
$env:CARGO_TARGET_DIR = '.tmp/performance-native-target'
npm run perf:native
```

- `perf:library`：1千、1万、5万条固定种子的生成曲目、100个手动列表；观察索引构建、标题排序、全匹配／无结果搜索与列表解析。每项排除一次预热、保留7次原始耗时及当前 Node 进程 CPU、调用结束时堆变化，记录环境、夹具与结果顺序哈希。仅测模型计算，没有 DOM、音频或图片读取。
- `perf:search`：从指定 Git 提交读取参考源码并独立打包，与当前源码在同一 Node 进程对照。两次预热后按 AB／BA 交错顺序各采7次；每对结果必须内容及顺序哈希一致。GC 排除在计时外，分别记录调用结束时未回收堆、保留返回值后 GC 的堆、释放返回值后的堆。前者不是峰值，后者不能单独证明不存在泄漏；RSS 也不是整个 Zone/WebView 的内存。
- `perf:native`：显式运行的 release Rust 测试，不创建 Tauri 应用或窗口。生成1千、1万、5万条 SQLite 记录及100个列表，测首次进程读取、同进程热读取和 JSON 序列化；另生成100／1000个一秒 PCM WAV，测解析和扫描入库。编译、夹具构造不计入样本，目录带生成标记，子进程只接受本工作区 `.tmp/perf/` 下的夹具。首次进程读取包含首连接／结构检查，文件已被构造过程访问，不能称为冷磁盘或应用冷启动。

`performance_observation.rs` 的两项测试默认忽略，仅上述入口显式执行。它们校验夹具和返回数量，不设未校准的产品耗时阈值。7个样本的 p95 是样本最大值，不能解释成稳定的统计保证。运行时间、硬件、Node/Rust版本和原始样本放本地调查记录，不固化成长期性能承诺。

## 真实前端与正在播放

真实浏览器验证应使用独立临时 profile、生成数据和产品的实际组件／CSS，区分模型计算、React提交、布局／绘制、输入到可见结果的时段。程序化滚动的帧间隔不能替代真实鼠标滚轮、完整页面和原生 WebView 的体验结论。测试夹具的原生接口替身必须标注；不得把模拟数据或 `audio.play()` Promise 当作出声测量。

正在播放以正常动效、真实尺寸／DPR、可追溯封面和照片负载测量；记录实际使用的 Canvas/WebGL 路径，不能把无图、静态、减少动态效果或软件渲染的数据冒充完整硬件表现。局部拼贴组件不代表艺术家照片、光焰、歌词和控制区的完整组合。帧间隔、浏览器主线程耗时与 GPU 执行时间分别报告；没有可靠 GPU 计时或进程归属就明确未测量。

原生运行沿用 [产物测试与隔离边界](../../packaging/README.md#github-ci-与原生产物测试)：准确 exe／来源 SHA／CI 身份、全新 profile、正式 Shell 项目前后快照均须核对。宿主禁止启动或未经批准的远端分支推送，不能借性能测试绕过。已有 `tests/native/nativeBaseline.mjs` 仅覆盖两首 WAV、浅色暂停和 reduced-motion，不能代表大库、冷启动或正在播放性能；`samplePodcastProcess.ps1` 的进程采样也不提供 GPU 帧时间。

## 搜索计算边界

搜索仍按原有匹配评分和 `zh-CN` 数字排序输出，中文、大小写、全半角及同分稳定顺序不得因优化改变。排序器只复用这一固定 locale／选项组合；曲目查找与评分仅在单次查询内共享，不保留跨查询或跨曲库缓存。手动列表保留原序、重复项和缺失项过滤；智能规则、收藏、活动统计与排除仍交给原有解析器。`SmartPlaylistContext.trackById` 如提供，必须对应同一个曲目数组，不得复用旧曲库的映射。

# 播客：产品语义、播放与网络边界

## 语音增强

默认与每节目播放偏好支持语音音量均衡及静音段加速，默认关闭。处理复用 App 的唯一音频图，具体边界见 [播放与正在播放视觉](playback-visuals.md)。静音加速保留原始时间轴，进度、章节和转写仍使用媒体时间；所选倍速与临时实际倍速分开，均衡不抵消用户音量。

## 时间书签与分享

收听页继续收听卡显示真实剩余媒体时长和最近进度更新时间；“查看全部”查询完整归档，以正在收听／最近收听或已关注范围分页，首页 8／12 集摘要不限制结果。单集行与继续收听卡同时提供可见的更多动作入口，支持键盘打开菜单和返回触发按钮。

常驻播客底栏直接提供倍速／睡眠选项与待播入口，连接、缓冲、失败和离线状态可见。底栏与全屏页面调用同一倍速与睡眠状态；打开待播采用一次性请求并选中待播分类，后续普通返回仍恢复浏览上下文。播放选项使用共享 Dialog 焦点隔离与 Presence 退场。

单集详情可在当前媒体时间添加备注、定位或删除书签。`podcast_bookmarks` 使用单集外键与毫秒时间唯一约束，同一位置更新备注；每集最多 100 条、总计 10000 条，位置有限且不超过已知时长。RSS 历史裁剪保留有书签的单集，完整备份包含书签。分享复制标题、时间和带 `#t=秒数` 的单集页面或音频链接；接收软件是否自动定位由其自身支持决定，Zone 不向外部发送消息。

备份恢复还验证命名列表条件、分组／书签标识及成员数量和播放偏好范围。导出失败只回滚本次创建的文件与空目录；恢复失败回滚数据库及本次复制的音频，既有文件不覆盖。已存在单集的音频来源改变时，不附加旧备份音频，也不留下新复制的无引用文件。

## 共享目录同步

`sync.rs` 提供默认关闭、用户通过原生目录选择器启用的关注与进度同步。每台设备只原子替换自己的 `zone-podcast-sync-<设备标识>.zonepodcast`，应用生命周期每分钟合并，最多 32 台设备／512 个目录项／每文件 64 MiB；用户自行配置网盘或共享盘负责文件传输，Zone 不接入未指定的云服务。关注与取消关注有独立更新时间，进度按最新更新时间合并（包括显式回退）；设备需保持系统时钟准确。合并快照只允许节目、已收听单集和进度表，不改变本机音频、待播、活动单集、设置或音乐。快照损坏逐设备报告，其他有效设备继续合并；目录失效保留本机资料并等待恢复。停止同步保留共享文件和其他设备。

同步目录、设备标识与已合并文件指纹属于 `podcast.sync.*` 本机设置，不导出，也拒绝从备份恢复，避免外部备份配置写入目录。原生校验绝对规范目录、普通文件和目录边界，合并继续使用正式备份 URL／标识／事务守卫。节目刷新不推进关注时间，显式关注变化才更新；已关注的旧资料以版本 0 参与初次同步。

本文由根目录 [AGENTS.md](../../AGENTS.md) 按任务索引引用。文中的行为与安全边界适用于相关改动；标为当前实现的参数用于定位，可在验证后调整。代码路径均相对于仓库根目录。

## 产品与模块边界

### 命名列表与智能列表

- 播放列表页区分当前待播与“我的列表”。命名列表存入共享 `zone.sqlite` 的 `podcast_playlists` / `podcast_playlist_items`；清空待播不清除命名列表，删除列表不删除订阅、进度或音频。
- 手动列表去重并保留独立顺序，最多 500 集。智能列表按完整数据库中的节目范围、收听/下载/稍后听状态、发布时间与排序动态计算，分页不会将前端已加载子集当作完整结果。
- 播放列表以事务将当前结果替换待播；空列表或超过 500 集时拒绝且保留原队列。前端串行执行队列修改，后续暂停、跳转、音乐切换或新队列修改阻止晚到结果自动开始播放。
- 编辑条件使用 `updated_at` 冲突检查；RSS 移除的单集仍被手动列表引用时保留。完整播客备份覆盖列表及成员，音乐列表语义独立。
- 资料库节目分组保存在 `podcast_show_groups` / `podcast_show_group_members`，支持多重成员关系。分组只筛选关注节目，编辑使用版本冲突检查；删除分组保留关注、下载和进度。组内顺序仍沿用资料库统一排序。

### 收听与播放

- 默认按“收听 / 发现 / 资料库 / 播放列表”组织。收听承载继续收听与关注更新，发现默认读取 XYZRank 中文播客榜，失败时回退 Apple 中国区榜单；搜索仍使用 Apple 中国区。手动 RSS 是辅助入口，下载用于离线收听。
- 预览、关注、稍后听与下载是独立状态。播客单集、队列、倍速、睡眠定时和进度不得进入音乐队列、收藏、播放统计或音乐节拍预分析。
- `src/views/PodcastView.tsx` 是页壳；`src/views/podcast/usePodcastViewModel.ts` 持有状态机与加载编排；屏组件经同目录 `api.ts` 调用命令，不直接 `invoke`。`cache.ts` 的模块缓存单例保持统一。
- `src/hooks/usePodcastPlayback.ts` 拥有单集会话与队列业务，通过 `podcastTransport.ts` 的窄接口接入 `usePlaybackControls.ts`；不要在视图创建另一套播放 ref 或绕过播放尝试门闩。
- `PodcastPlayerBar` 与 `PodcastNowPlayingView` 提供独立播客控制，不复用音乐正在播放页的拼贴或歌词内部状态。音源仍复用 App 唯一的 `<audio>`。
- 保存单集称“稍后听”，插入待播首位称“下一集播放”；节目/单集详情保留一个内容大标题，功能性文字可读性见 [组件规范](../component-guidelines.md)。

- 播客正式链路：默认“收听”页展示继续收听与关注更新，“发现”页展示热门节目；发现结果可先预览再关注，关注、稍后听与下载状态相互独立。未下载单集通过受控 `zone-podcast` Range 代理即时播放，已下载单集通过 `zone-audio` 本地播放，进度每 5 秒节流且按调用顺序保存；使用独立播客底栏、全屏正在播放和可跨重启恢复的当前单集与待播队列。待播项只在对应音源实际开始播放后消费；单集自然结束会进入待播首项，睡眠定时可在指定分钟或本集结束后暂停。
- 睡眠定时、手动播放/暂停、切换到音乐及卸载会失效尚未返回的自动续播请求；迟到结果仍同步已提交的待播队列，但不能重新启动播放。
- 媒体元素仍有错误时，迟到的 pause、waiting、canplay 和 loadstart 事件保持错误态；只有显式重试或切源清除媒体错误后才重新进入加载流程，避免重试入口被缓冲状态覆盖。

## 状态与持久化

- 资料库提供 OPML 订阅导入导出。导入仅改变订阅，复用正式 RSS 地址校验、网络配额和保存入口，最多并行 3 个；失败的节目逐项报告，成功订阅及已有进度不回滚或覆盖。文件限制 5 MiB／500 个去重地址，拒绝 DTD 和外部实体。OPML 不携带进度、待播、设置或音频，完整资料备份使用独立格式。
- `.zonepodcast` 资料备份包含播客表、独立原生设置及 `zone-podcast-` 界面偏好，可选复制已下载音频到相邻受控目录；携带音频时须一起保存文件和目录。清单上限 64 MiB，音频逐文件 SHA-256 校验且限制 2 GiB。恢复仅合并播客资料，以更新时间合并进度及原生设置，不接收备份中的本地绝对路径、断点凭据或运行请求，不改音乐表；导入事务失败回滚，复制的新文件仅按明确生成路径清理，已有文件不覆盖。播放器会话与界面偏好在重启后恢复。

- 应用启动后由 Rust `maintenance.rs` 在应用生命周期内刷新关注节目，离开播客页面不停止。`podcast_download_jobs` 保存等待、运行、暂停与失败任务；退出后的运行任务重新排队，主动暂停不会自动恢复。单集详情下载与后台任务共用文件守卫、受控网络及版本校验续传。
- 节目设置支持自动下载最新 N 集，先确定最新 N 集再排除已听与既有下载，避免逐批下载整档节目。自动清理只处理已听完、未稍后听、未待播且不是当前单集的受控下载；空间设置限制新增下载，已保护文件不会为满足上限而强删。自动下载和清理默认关闭，空间默认不限。设置读取损坏时保留原记录并停止相应维护。

- 播客状态与音乐保持业务隔离，不写入音乐表或旧音乐 `localStorage` schema；节目预览/关注状态、单集、稍后听、待播顺序、下载与进度使用应用数据目录 `zone.sqlite` 中的播客表，旧 `podcasts.sqlite` 只作迁移源。音频位于同目录下的 `podcast-downloads/`。预览节目可以入库但不出现在资料库，`subscribed` 只表达用户是否关注。Feed 刷新时若单集已从源消失，仅在无进度、未稍后听、未排队、无进行中/完成下载时删除该行；有用户状态的单集会保留。`enclosure_url` 变更会失效对应离线下载。普通进度写仅允许前进，显式 seek/flush 传 `force` 才可回退。播客倍速、自动续播模式与兼容的当前单集记录保存在 `zone-podcast-playback-v1`；当前单集另以独立键 `podcast.active_episode.v1` 保存在 SQLite `app_settings`，优先用于重启恢复，避免 WebView 尚未落盘时丢失活动单集。原生记录缺失时迁移浏览器记录，原生读取失败时保留原记录并暂停该键自动写回；写入串行且跳过已被后续选择替代的排队任务，失败后每 5 秒重试最新选择，成功的进度保存也可提前触发重试，卸载时取消计时器。最后单集重启后以暂停态恢复且不改变音乐播放速度；睡眠定时只存在于当前运行会话。

## 单集列表与时长

- 简介经 `podcastNotes.ts` 解析为允许的排版节点，不插入原始 HTML、脚本、样式或远程嵌入。HTTP(S) 链接和文本 URL 经形状及原生 DNS 检查后交给系统浏览器，功能时间码复用显式播放位置；不创建额外音频元素。章节相关链接共用此入口。
- RSS 转写由 `transcripts.rs` 按需加载，支持 WebVTT、SRT、Podcasting 2.0 JSON、纯文字及转为文字的 HTML；带时间段落可查询、跟随播放和点击跳转。仅请求 HTTPS，沿用网络配额、取消、重试、DNS／重定向及 8 MiB 响应限制；最多 20,000 段。段落缓存位于 `podcast_transcript_cues`，24 小时内复用，之后条件请求；网络失败显示已有缓存并保持旧时间。界面每页最多 50 段，搜索覆盖完整转写，跟随动作使用立即滚动。

- 原生节目偏好支持“使用默认播放设置”及独立倍速、片头／片尾、前进后退间隔和同节目续播方向。共用 transport 在偏好读取结束后才绑定播客来源；等待期间保留显式时间码和暂停意图。播放偏好加载失败使用会话默认值并提示，原记录保留；节目倍速不改音乐速度或默认播客倍速。片头只影响普通播放／恢复，显式章节时间保持原位置；片尾仅在确有足够正片且正在播放时完成本集，重复结束事件不会再次消费队列。

- `search.rs` 在 SQLite 中查询整个已入库节目与单集档案，搜索标题、作者与简介；节目页支持未听、已听、下载、稍后听筛选和日期／标题排序，每页最多 100 条，界面每页 50 条。搜索不依赖已加载列表或网络，LIKE 通配符按字面转义，排序及筛选只接受枚举。界面请求按查询生命周期丢弃过期页，节目搜索条件在本次应用会话中保留。
- 发现页在线搜索失败时先匹配关注节目与持久榜单，无缓存才请求发现目录；明确标注“本地节目及榜单内匹配结果”。本地单集查询独立显示，榜单内检索不等于完整平台搜索。热门目录支持分类与未关注筛选，默认仍呈现完整目录。

- 列表数据仅作为媒体快照，不能覆盖播放会话的最新进度。会话在每次音频时钟更新时保留最新位置与真实时长（数据库写入仍节流），切源前 flush；再次从旧列表播放时优先采用会话记录。显式 seek 和已播／未播标记更新同一记录，暂停后的未播标记继续遵循进度写入抑制规则。
- 单集异步操作返回后按 episode ID 更新列表及播放域，只在当前详情仍属于该单集时替换详情；保存、播放标记和离线删除不能覆盖期间打开的其他单集或重新打开已关闭的详情。

- 节目单集列表 `podcast_list_episodes` 默认读取 100 集，支持 `offset`/`limit`（最大 200）；节目页按需加载更多，非活动单集使用 memo 隔离进度刷新。主列表、单集详情和待播优先读取已知真实媒体时长；RSS 时长按秒、MM:SS、HH:MM:SS 严格解析。旧 `duration_parser_version` 在下一次刷新时绕过条件请求重新获取，保留用户进度和待播状态。

## 网络、代理与离线文件

- 在线播放额外使用按单一音源隔离的前端恢复门闩：等待 15 秒不推进或媒体网络错误时最多恢复 3 次，错误退避为 1/3/8 秒；离线等待 `online`，只有实际音频时钟推进才重置预算。暂停、手动继续的播放代次、切源与卸载使旧恢复失效；解码内容错误不自动循环重试。
- 下载启用空间上限时按数据库共享写锁串行准入；不限空间的任务共享读锁，设置上限后的新任务先等待已开始任务结束。空间按受控文件的实际字节计入已下载及其他单集断点，当前任务用完整文件预算逐块检查，未知或错误的来源长度不能越界写入。新限制在任务开始时应用，不截断已开始的下载。
- 自动清理在同一立即写事务内复核已听、当前单集、待播、稍后听、手动列表及最新清理设置，候选快照不能取消这些保护。暂停或失败任务可手动清理断点，任务保持暂停以避免下一轮自动重新下载；完整音频须从已下载资料库管理。
- 回到前台、窗口焦点与页面恢复时先核对睡眠截止时间，已到期先暂停，再处理连接与 AudioContext。输出设备集合发生变化时暂停播客并提示用户确认；不请求麦克风权限，不因输入设备变化启动播放。
- Windows 系统媒体控制沿用原生 SMTC；系统暂停即使媒体当前处于缓冲暂停态也会撤销播放意图。系统“上一项”使用节目的后退间隔，定位拒绝非有限数值并钳制到实际媒体范围。

- 榜单编排位于 `discovery.rs`：固定请求 `https://xyzrank.com/api/podcasts?limit=50&offset=0`，最多展示 24 个带有效公开 RSS 地址的节目，按规范化 RSS 去重并生成稳定 ID。XYZRank 请求共用 Metadata 配额、取消、重试及地址校验，整体预算 10 秒，响应上限 2 MiB。目录只检查 RSS 地址形状；打开节目后由既有 RSS 入口验证实际 Feed，播放和下载继续校验音频地址、重定向及内容，不依赖小宇宙私有接口。榜单可访问不代表每个 RSS 或音频 CDN 都可访问。
- 每个来源只保存最近一次成功榜单，分别使用 `zone.sqlite` 的 `app_settings` 键 `podcast.discovery.xyzrank.v1` / `podcast.discovery.apple.v1`，属于派生缓存，不改变关注、进度、队列或音乐状态。发现页先恢复内存／原生缓存，15 分钟内免于重复联网，过期后保留内容并刷新。XYZRank 失败后尝试 Apple，两者失败时使用最新成功快照并标记“缓存”，没有快照时显示重试入口；失败不会更新缓存时间。取消请求不能触发备用来源或返回缓存冒充成功。坏记录读取时跳过并保留，缓存写失败不阻断成功的网络结果。
- 发现页显示实际榜单来源及刷新状态，Apple 回退明确标记“备用来源”；“刷新榜单”绕过新鲜度判断重新尝试主来源。来源没有增加设置项或独立播放器。

- 播客网络请求由 `src-tauri/src/podcast/`（`network.rs`、`tasks.rs`、`proxy.rs`、`discovery.rs` 与 `apple.rs`）专用客户端处理：Apple 搜索固定 `country=CN`；RSS/音频只允许 HTTP(S)，每次重定向重新校验并固定解析地址，拒绝凭据、fragment、非 80/443 端口与内网/环回 IP。为兼容大陆常见 Clash fake-IP，仅允许“域名解析所得”的 `198.18.0.0/15`，直接输入该网段仍被拒绝。
- DNS、各次重定向、连接、响应头及正文共用总截止时间；连接最多 10 秒，等待响应头和每次正文读取停滞最多 30 秒。下载总预算为 4 小时，正常持续传输的慢连接不再受原先 30 分钟上限影响。
- Apple 榜单使用上游提供的 25/50 条地址，再按界面请求数量截取，不把任意数量拼进上游路径；所有受控 GET 统一处理临时 DNS／连接／读取失败及 HTTP 408/429/502/503/504，整个操作最多使用两次重试，退避带少量抖动；支持秒数或 HTTP 日期形式的 `Retry-After`，等待超过剩余预算时直接返回。正文失败会重新验证完整响应，下载只按已校验版本续传，格式、大小和地址校验失败不重试。
- RSS 响应上限 20 MiB，音频上限 2 GiB；下载目标只按数据库中的 episode ID 生成，先写 `.part`；断点在 SQLite 记录原始地址、最终地址、强 ETag 与完整大小，续传向同一最终地址发送 `If-Range`，仅在地址、强 ETag 与大小一致时追加。版本变化或失效断点回退完整请求，没有强 ETag 的来源和旧断点安全重下；先截断旧内容再保存新版本，保存后才写入响应。206 响应必须声明完整文件大小，范围、响应长度与实际读取字节数必须一致；收齐整个文件并通过音频魔数后才原子落盘，未完成的响应保留断点供重试。
- 删除播客下载只允许清理由数据库 episode ID 推导且位于受控下载目录中的最终文件与精确 `.part`；下载和删除对同一单集互斥，不能让前端传入任意文件路径。
- RSS 换源及下架清理共用同一数据库的单集文件互斥锁，锁保持到事务提交后的文件清理完成。换源遇到同集正在下载或清理时回滚刷新并提示重试，普通元数据刷新不受影响；下载落盘与保存结果在同一事务内复核原始音频地址，旧音源的失败回调也不能重建新音源的下载状态。
- `zone-podcast` 协议只接受数据库中的 64 位 episode ID，绝不接受前端传入的远程 URL；每个 Range 响应最多代理 1 MiB，带 CORS，逐跳应用相同 SSRF 校验。通用二进制 MIME 验证文件起始数据，后续中段与尾部复用按 URL、长度及响应版本区分的有界短期验证缓存；直接 seek 或首块过短时用受控的 32 字节 Range 补做验证。上游不支持 Range 且内容超过单块上限时明确失败，由用户选择离线下载。
- HTTP 代理按 `ZONE_PODCAST_PROXY`、对应的 `HTTP_PROXY`／`HTTPS_PROXY` 环境变量、Windows 当前用户手动代理依次选择；`ZONE_PODCAST_PROXY=direct` 可直连，遵循 `NO_PROXY` 与系统代理的域名绕过列表。受控本地桥将上游 CONNECT 目标改为经过校验的数字 IP，原域名继续用于 Host、SNI 与证书验证，代理凭据只发送给配置的代理。缓存按代理配置与校验地址隔离，通道由应用运行时管理而不依附临时调用方，后续连接轮换已校验的地址，活动正文保留通道租约，握手／空闲时间和通道数有上限。HTTP 来源要求代理允许 CONNECT 对应端口；PAC 与 SOCKS 不在当前支持范围。
- 元数据、封面、流式播放和下载各自最多并行 4/4/6/2 项，排队有容量上限且最多等待 30 秒；额度覆盖正文读取。RSS 刷新使用滚动窗口，一项完成即补下一项。新搜索、切换音源、封面卸载与页面卸载会通过请求 ID 取消过期的原生网络等待；单集与批量下载共用请求登记，同集的重复调用复用在途任务；返回播客页后仍可取消后台下载。下载通知提供“取消下载”，保留已校验版本的断点，并停止批量任务的剩余单集。取消与网络截止时间不打断数据库或文件事务，先到的取消信号也会短期保留以覆盖 IPC／协议到达顺序。
- RSS 与目录返回的远程封面不得直接作为 WebView 的 `<img src>`；统一先编码为 URL-safe token，再经 `zone-podcast-artwork` 代理。代理逐跳校验 DNS/重定向，限制 8 MiB，只接受受支持的图片 MIME 与匹配的文件魔数。

## 验证

- 前端模型、命令接线、播放分支或 UI 变化：`npm run build`、`npm test`，重点看 `tests/podcast*.test.mjs` 和 `tests/playbackTransport.test.mjs`。
- Rust 数据库、网络、协议与下载变化：`cargo check`，补充并运行对应模块测试。真实网络 smoke 默认忽略，仅在显式设置 `ZONE_PODCAST_LIVE=1` 后运行。
- 播放交互变化实测音乐与播客切换、播放失败/缓冲、暂停后恢复、自然结束续播及待播仅在实际开始后消费；进度相关改动检查 seek 回退、重启暂停恢复与失败重试。列表改动检查加载更多和非活动单集不会随进度无谓重绘。
- 启动应用沿用根目录的会话授权规则；协议/打包相关改动还需 `npx tauri build --no-bundle`。

### 原生稳定性测试

- `npm run test:podcast:stability -- --phase=discovery --minutes=1 --cycles=1` 使用隔离榜单及 RSS 服务器验证目录解析、SQLite 缓存恢复、双来源失败、Apple 回退与主来源恢复，并经正式节目页、播放 hook 和下载入口完成一条 RSS 单集流程。检查两种窗口尺寸、刷新焦点及 reduced-motion 分支，原生截图保存在同轮报告目录；捕获依赖仅加入测试副本。`live_xyzrank_catalogue_has_playable_rss_candidates` 是显式 `ZONE_PODCAST_LIVE=1` 下运行的忽略测试，用正式网络入口检查真实榜单和首个 RSS，夹具成功不代表所有运营商、RSS 或音频 CDN 的可达性。

- Windows 上先运行 `npm run build`，确保 Cargo 依赖已缓存，再运行 `npm run test:podcast:stability`。默认执行 200 次在线／离线切源、暂停恢复、10 次网络失败重试、截断下载续传、播放／下载期间强制退出并重启，以及真实时间的 120 分钟连续播放。`-- --minutes=30 --cycles=200` 可调整时长；时长上限 240 分钟，切源上限 2000 次。
- 测试入口为 `tests/run-podcast-stability.mjs`，原生与前端夹具在 `tests/native/`。夹具调用正式播放 hook、SQLite、下载与媒体协议实现，只有源码副本允许访问本地故障服务器；正式网络校验、CSP、capabilities 与用户资料不改变。每轮使用独立数据库、WebView 资料目录及测试音频，进程树只监测本轮启动的播放器及其子进程。测试报告、隔离数据库与媒体产物位于 `.tmp/podcast-stability/`，Cargo 编译缓存可用 `--target-dir` 单独指定。
- 连续播放每 30 秒检查真实音频时钟、持久化进度和唯一 AudioContext；每 10 秒采样私有内存、句柄和进程数量。报告给出暖机后的趋势与首尾中位数，资源数据需要结合缓存及进程变化判断，不能仅用一次峰值宣称泄漏或无泄漏。下载完成后校验 SHA-256，恢复场景检查 SQLite `integrity_check`。
- 快速复测使用 `npm run test:podcast:stability -- --phase=short --minutes=1`；`--switch-rounds=3 --cycles=2000` 可连续测三轮，每轮后暂停 30 秒观察资源回落，轮数上限为 5。`--phase=network` 单独检查真实播客页的取消下载、两种窗口尺寸与键盘焦点，并在原生 WebView 应用正式 reduced-motion 规则检查收敛分支；它不修改系统动效设置。`--phase=crash-playback` 和 `--phase=crash-download` 各自包含一次强制终止与重启。默认播放 10 秒后终止；`--crash-delay-ms=1000` 专门探测新单集设置尚未落盘的窗口。SQLite 进度和 WebView `localStorage` 是不同持久化链路，不能把数据库完整等同于当前单集设置在突发终止时已保存。
- 磁盘空间与虚拟机暂停测试另用 `tests/run-podcast-stability-hyperv.ps1`，参数为 `-VMName`、`-CredentialFile`、`-PreparedReport`。先运行 `npm run test:podcast:stability -- --prepare-only --minutes=1`，再把返回的报告目录传入 `-PreparedReport`。只接受备注包含 `Zone MSIX disposable test VM` 的专用 Hyper-V 测试机，凭据沿用 [发布测试配置](../../packaging/README.md) 的 DPAPI 文件，客体需有已登录的测试用户和 WebView2。
- Hyper-V 夹具创建全新的 64 MiB VHDX，只在核实新增磁盘身份、大小与 RAW 分区状态后格式化，要求客体 `R:` 未占用。填充同时需要显式开关与测试卷标记，最多写入 128 MiB；WebView 资料留在客体系统盘。真实写满后验证进度和下载失败、释放空间后的恢复，结束时卸载测试卷并恢复原本关闭的虚拟机。
- 虚拟机保存／恢复覆盖暂停后定时器收敛和媒体继续播放；它不等同于 Windows S3/S4，客体时钟也可能暂时冻结。真实待机、休眠、蓝牙设备切换与真实运营商网络仍需在支持这些条件的机器上补测，报告必须区分实际覆盖范围。

- 发现页显示实际榜单来源与快照更新时间；刷新失败保留原时间。关注标记与原始排名同时显示，筛选不重排榜单名次。节目按钮保留完整标题与作者供悬停和辅助技术读取。

- 节目简介默认两行，可展开全文；节目首屏优先露出单集。各主屏与节目保留会话内滚动和单集焦点，分页、筛选、命名列表选择返回时恢复。资料更新保留已有搜索行，输入法组合结束后才发起本地查询。

- 资料库以节目、完整单集、稍后听、下载、历史、管理轻量分类组织。备份／同步与下载任务位于管理页；封面数字明确表示包含历史单集的未听完数量，24 小时内更新另行标注。

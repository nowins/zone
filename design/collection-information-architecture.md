# 收藏的信息架构与浏览设计

状态：目标设计，尚未接入正式应用。2026-09-08 基于当前源码和本地曲库只读样本梳理。本文定义一次完整改造的范围，不能据此把下述能力视为已经实现；当前实现仍以 [组件规范](component-guidelines.md) 和 [架构地图](engineering/architecture.md) 为准。

## 1. 要解决的用户任务

用户听到一首歌后，应该能了解这首歌、打开所属专辑、进入艺术家、找到其他本地作品，再回到原来的浏览位置。整个过程可以持续播放原来的音乐。

收藏中的四个分类是同一个音乐库的不同入口。歌曲、专辑、艺术家和播放列表有各自的身份与详情，所有入口打开同一个对象；播放队列和资料编辑分别有独立职责。

验收主线：播放列表 → 歌曲详情 → 所属专辑 → 艺术家 → 另一张专辑 → 连续返回到原播放列表。一路浏览不改变播放源、队列、进度、随机或循环模式。

## 2. 当前问题与依据

| 当前事实 | 用户感受与后果 | 定位 |
| --- | --- | --- |
| 通用信息面板对所有对象读取 `payload.tracks[0]` 的专辑、艺术家和文件名 | 艺术家、专辑与播放列表的信息被某一首歌代替，页面回答错了问题 | [InfoPanel](../src/components/InfoPanel.tsx) |
| 艺术家视图默认选中第一张专辑，只显示这张专辑的歌曲 | 点击艺术家后看见的是一个下钻选择器，难以知道艺术家的整体作品范围 | [ArtistBrowser](../src/views/ArtistBrowser.tsx) |
| 专辑详情里的艺术家是普通文本；歌曲行的艺术家、专辑也没有导航动作 | 已经看到关系，却不能顺着关系继续探索 | [LibraryView](../src/views/LibraryView.tsx)、[CollectionTrackList](../src/components/CollectionTrackList.tsx) |
| 导航由页面、分类和若干选中值组合，缺少对象详情与逐级返回记录 | 同一个对象从不同入口到达的状态不同，跨对象浏览后无法可靠回到原处 | [useNavigation](../src/hooks/useNavigation.ts) |
| 搜索歌曲单击即播放；收藏歌曲单击选择、双击播放 | 相同内容在不同入口有不同后果，用户可能意外替换队列 | [SearchResultsView](../src/views/SearchResultsView.tsx)、[CollectionTrackList](../src/components/CollectionTrackList.tsx) |
| “在收藏中打开”不支持歌曲；艺术家和专辑的“添加到收藏”实际是批量喜欢歌曲 | 操作名称不能准确表达作用对象 | [ContextMenu](../src/components/ContextMenu.tsx)、[usePlaylists](../src/hooks/usePlaylists.ts) |
| 艺术家按曲目里的完整字符串分组；专辑由名称与专辑艺术家组合分组 | 当前是从歌曲派生的索引，还没有可直接用于全部详情页的统一对象模型 | [useMusicLibrary](../src/hooks/useMusicLibrary.ts)、[music](../src/utils/music.ts) |

本轮在浏览器中直接渲染现有 `LibraryView`、`ContextMenu` 和 `InfoPanel`，用本地 SQLite 的 13 首歌曲文件标签与真实封面只读快照复现了前三项。这组组件证据使用未加载补充资料的状态。示例“刺猬”有本地 3 首歌、3 个专辑分组；信息面板仍展示其中第一首歌的专辑和文件名。

数据库还保存了已经采用的艺术家简介、别名与图片，说明问题也包括资料组织与呈现，而非单纯缺少数据。交互稿额外接入了“刺猬”的已缓存资料，展示有资料时的身份区和简介展开；无资料时保留简洁的作品浏览。线上提供方的专辑／歌曲数量没有混入本地数量。

验证边界：这是现有组件的浏览与展示检查。开发应用进程存在，但本轮原生自动化没有取得可定位窗口，未重复启动。组件快照未接入真实播放、在线资料获取或资料写回；不把这部分检查宣称为完整 Tauri 流程审查。截图和交互稿存于被忽略的本地 `docs/collection-information-review-2026-09-08/`，不作为其他 checkout 的必需依赖。

## 3. 对象与关系

| 对象 | 回答的问题 | 直接关联 |
| --- | --- | --- |
| 歌曲 | 这首是什么、由谁演出、属于哪个版本、我在哪里收录过 | 演出艺术家、所属专辑、包含它的播放列表 |
| 专辑 | 这张作品是什么、由谁发行、我本地有哪些曲目 | 专辑艺术家、按碟号／曲号排列的本地歌曲、各曲目的演出艺术家 |
| 艺术家 | 这是谁、我本地有哪些他的作品 | 以专辑艺术家身份署名的专辑、参与演出的歌曲与专辑 |
| 播放列表 | 我组织了哪些歌曲、以什么顺序播放 | 有序歌曲；通过歌曲继续进入艺术家和专辑 |
| 当前队列 | 接下来实际会播放什么 | 队列条目与歌曲；属于播放状态，不冒充持久歌单 |

歌曲文件是当前音乐库中最稳定的记录。不同文件即使同名，也不能直接合并为同一录音；现场版、重制版、不同专辑中的版本允许分别存在。播放列表通过歌曲 ID 关联，不因浏览或显示名称变化而改序。

“喜欢”继续只作用于歌曲。默认 `favorites` 播放列表的展示名建议改为“喜欢的歌曲”，保持既有 ID 和数据语义。顶层“收藏”仍表示整个本地音乐库。不在这次改造中顺带引入关注艺术家或收藏专辑的新数据类型。专辑／艺术家的批量喜欢若保留在菜单，明确写“喜欢这些歌曲”，并在动作中表达范围。

## 4. 页面与导航层级

### 收藏入口

保留“艺术家 / 专辑 / 歌曲 / 播放列表”四个入口、搜索和现有 Zune 排版。艺术家索引适合按名称快速定位；专辑索引适合封面浏览；歌曲索引用完整歌曲表；播放列表索引保留用户自己的组织顺序。

艺术家和专辑条目的主动作统一为进入对象详情，播放使用独立按钮。这是对当前“只改变旁边预览”的明确调整。键盘移动仍只移动焦点，不触发播放。歌曲行继续保留桌面选择与播放习惯，详见第 6 节。

### 对象详情

详情占用收藏内容区，避免继续在三个窄栏里挤入资料、封面和歌曲。固定外壳只有全局导航和底部播放器，内容区统一包含：

1. 返回入口与对象类别。返回提示来源，如“返回搜索结果”；类别链接可直接进入该分类索引。
2. 唯一的对象标题、身份信息和主动作。
3. 本对象的作品、关系或内容。资料较多时就地展开或使用对象内部标签。

详情中的“概览 / 专辑 / 歌曲”是艺术家内部视图，不再复用收藏四分类作为它的内部标签。内部标签、排序、局部筛选更新当前历史条目的状态，不每点一次都增加一个返回步骤。

### 返回契约

- 各入口统一调用对象导航，记录目标和来源，不再由调用方分别设置 `view`、`selectedArtistName`、`selectedAlbumKey`。
- 返回恢复原页面、查询词、筛选、排序、选中对象、滚动锚点与键盘焦点；长列表用条目 ID 加偏移恢复，不能只保存一个容易失效的像素值。
- 页面返回、Alt+左方向键与鼠标后退键采用同一历史动作；前进对称处理。对话框优先处理自己的键盘动作。Esc 关闭浮层或退出全屏，不顺带退出资料页。
- 同一对象重复打开不叠加相同记录。浏览环路允许逐步返回，不把“类别层级”误当作实际访问历史。
- quickplay、搜索和正在播放都可以成为来源。顶层导航离开收藏时保留收藏会话；从正在播放进入资料后，返回可恢复原正在播放界面。
- 对象已被移除时展示简洁的不可用状态和返回入口，不能悄悄改成第一位艺术家或第一张专辑。
- 浏览动作不触碰 transport；点击“播放”才以明确来源生成播放请求。

## 5. 四种详情页

### 艺术家：先认识对象，再浏览作品

首屏：艺术家名称、可用的真实人物／乐队图、本地专辑与歌曲数量，以及“播放本地歌曲”“固定到 quickplay”和次级资料入口。没有可信艺术家图片时，以排版和作品封面呈现，不把任意专辑封面当成人像。

概览优先显示本地作品：专辑封面列表与歌曲列表。资料存在时增加简介摘要和展开入口；缺少简介不放大块空卡，也不制造生平文案。专辑和歌曲多时提供“查看全部”及内部标签。

专辑按照角色区分“专辑”和“参与的专辑”；同一专辑可以只在适合的位置出现一次。歌曲可查看全部本地演出曲目。仅在有真实个人收听统计时使用“常听”，不能用第一首或字母排序冒充“热门”。

“本地 3 首歌曲 / 3 张专辑”指当前曲库中的条目，不意味着完整唱片目录，也不表示已获得完整专辑。

### 专辑：封面、身份、曲目为一体

首屏为真实封面、专辑名、可点击的专辑艺术家、可用的发行年份／流派、本地曲目数和可确定的本地总时长。主动作“播放本地歌曲”，次级动作“加入队列”和更多操作。

曲目按碟号、曲号及现有稳定回退规则排列。合辑或曲目演出者不同时，保留逐曲艺术家链接。双碟显示碟分组，不能按曲号跨碟混排。未知总时长不伪造；只有本地曲目时不标“完整专辑”，也不绘制没有来源的缺失曲目列表。

页尾可提供同一艺术家的其他本地专辑，排除当前专辑。关系来自本地索引，不把所有其他封面当作推荐。专辑艺术家可以直接进入艺术家详情，不要求回到分类重新搜索。

### 歌曲：清楚的归属与版本

首屏为封面、歌曲名、可点击的演出艺术家、可点击的所属专辑、时长和已有版本信息。主操作是播放、喜欢、加入播放列表；歌词仍使用既有歌词能力，不复制一个新的加载系统。

正文优先显示有意义的关系：所属专辑的其他本地曲目、收录这首歌的播放列表。没有关系时省略该区块。收录关系包含手动列表和当前命中的智能列表，智能列表需标明类型，不能把动态命中当成手动收录。

格式、文件名、路径、标签来源放在“文件与资料”次级入口；按元数据实际可用字段展示，不推断采样率、位深、作曲或发行日期。浏览歌曲详情不重新开始播放。

### 播放列表：用户编排优先

保留已完成的左侧列表索引与右侧标题、歌曲表格布局。歌曲表连接到同样的歌曲／艺术家／专辑详情，无需另造一套信息页。

标题区保留真实封面组合、名称、描述、数量与播放。手动列表保留用户顺序；智能列表显示规则入口与规则结果；“喜欢的歌曲”和“正在播放”有明确类别，不能通过第一首歌曲推导列表艺术家、专辑或文件属性。

排序、过滤只影响浏览时，必须与“修改列表顺序”区分。播放器接收点击当时的播放来源快照，不随用户切换资料页或列表排序而变化。

## 6. 统一交互表

| 控件或入口 | 鼠标 | 键盘 | 导航／播放结果 |
| --- | --- | --- | --- |
| 歌曲行主体 | 单击选择，双击播放 | 上下／Home／End 移动；Enter／Space 播放 | 播放时使用该列表的明确来源 |
| 歌曲行“查看歌曲” | 单击打开详情 | 独立焦点，Enter／Space 打开 | 不播放；返回恢复该行 |
| 行内艺术家／专辑名称 | 单击打开对应对象 | 原生链接，Enter 打开 | 不向行主体冒泡播放或改变来源 |
| 艺术家／专辑索引项 | 单击打开详情 | Enter／Space 打开 | 独立播放按钮才播放 |
| 喜欢按钮 | 切换歌曲喜欢状态 | 独立焦点，Enter／Space 切换 | 不改变选择、页面或播放 |
| 搜索实体结果 | 打开相应详情 | 按实体控件语义 | 返回恢复原查询与结果位置 |
| quickplay 固定项 | 保留现有直接播放主动作 | 保留既有键盘主动作 | 通过更多操作“查看艺术家／专辑／歌曲”进入统一详情 |
| 正在播放的艺术家／专辑 | 打开对应详情 | 可聚焦的关系链接 | 返回正在播放；队列与进度保持 |
| 底部播放条封面 | 保留进入正在播放 | 保留既有行为 | 不改成打开歌曲资料 |

歌曲行的主体不能继续把全部列包在一个 `button` 里再嵌入链接。调整为同一行容器里的独立选择／播放区、关系链接、查看歌曲与喜欢控件；焦点顺序和方向键只管理歌曲行主体，Tab 可以到达关系与动作。指针双击艺术家链接也不能触发歌曲播放。

关系链接默认保持次级文字，使用低对比下划线或清楚的链接标识表达可点击性，悬停／聚焦提亮；不要把整张表染成粉色。长名称保留省略和完整可访问名称。右键与 Shift+F10 提供相同对象菜单。

菜单按对象给出“查看歌曲 / 查看专辑 / 查看艺术家”；歌曲菜单另有“前往专辑”和“前往艺术家”。多位可信署名艺术家采用就地选择菜单，不擅自只选第一位。原“查看信息”拆为对象详情与“编辑资料”，不再以模糊名称指向两个不同任务。

## 7. 元数据、空态与错误

- 本地标签与已采用的补充资料先渲染，在线补充不阻塞浏览、不成为打开页面的前提。在线请求继续走既有 Rust 受控入口。
- 资料编辑是次级对话框或面板，清楚显示当前对象和修改范围。艺术家编辑不出现某首歌的专辑／文件；批量专辑编辑先明确受影响歌曲。
- 资料来源与覆盖层说明只出现在资料管理任务中。用户需要作出来源选择、恢复或编辑范围决定时才展示这些细节。
- 字段有冲突时保留来源，不能把不同对象的字段拼成一个“完整”简介。请求按对象和版本取消／校验，切换对象立即清理旧上下文；迟到响应不覆盖当前详情。
- 艺术家署名和专辑艺术家是不同角色；“群星”不能伪装成单个表演者。没有结构化署名时，保留原始字符串，不按 `/` 自动拆分，例如 `AC/DC`。
- 不把去掉全部标点后的字符串当作可靠身份。当前 `normalizeArtistIdentity` 用于补全匹配，不应原样成为对象主键。同名艺术家、同名专辑和发行版本需要保守处理。
- 搜索无结果、空列表和不存在的对象使用短空态与可执行返回／清除筛选入口。无图片使用既有 `Cover` 占位；不存在艺术家资料时省略简介区。
- 不以空列表、网络失败或解析失败触发数据库清理。迁移与覆盖恢复继续遵守 [持久化规范](engineering/persistence.md)。

## 8. 视觉与动效

保持 Zune 的低字重标题、内容封面与轻量导航。对象标题是页面唯一大标题，艺术家与专辑关系紧邻标题；功能正文 400 字重，曲名约 14–16px、辅助信息约 12–13px。桌面默认 1180×760 下，详情标题约 36–48px，封面约 160–184px；最小 920×620 时收紧间距与封面，优先让主要关系和第一组作品可见，而不是缩小正文。

详情正文以一个主滚动区为主。长简介按需展开，作品较多使用完整内部视图；不增加长期并排的窄信息栏。播放列表保留索引与内容两个独立滚动区。图像和背景低对比，不在歌曲文字后反复堆叠人像与高反差封面。

进入详情与返回体现方向，复用 `requestNavigation` 及统一动效；内部标签采用较短内容过渡，历史返回不重播全部列表级联。封面共享变换复用现有 FLIP，不写另一套动画引擎。持续播放或更新进度不能重置详情页动画。所有新增动效消费 [motion tokens](../src/motion/tokens.ts)，reduced-motion 下保持直接、稳定的状态切换。

## 9. 实现划分

先形成统一模型与一条完整浏览路径，再扩展所有入口；不先造四个只靠名称互相猜测的页面。

### A. 关系索引与导航骨架

新增只读的曲库关系索引，集中处理歌曲、专辑分组、艺术家署名、播放列表收录关系与显示字段。第一阶段从现有音乐主数据派生，不新增第二份持久歌曲库。目标接口可用 `CollectionEntityRef`、`CollectionLocation`、`openCollectionEntity`、`goBack` 和 `goForward` 表达，命名在实现时统一。

`CollectionLocation` 包含索引／搜索／实体详情目标及浏览状态，和 transport 状态分离。实体引用不能依赖 `tracks[0]`，也不能直接拿元数据接口返回的 `field-merge:{kind}` 聚合标记当作稳定 ID。当前歌曲 ID 和播放列表 ID 可直接使用；专辑／艺术家先使用集中解析的分组引用，并保留歌曲锚点用于改名后的精确对账。无法唯一解析就显示不可用，不做猜测跳转。

如需要跨重命名、重新扫描、同名实体拆分后长期稳定的艺术家／发行 ID，应单独设计数据库迁移：审核现有 `metadata_entities` 与链接表的用途、迁移与恢复路径后再实施。元数据提供方实体不能未经验证直接升级为全库身份。

### B. 首个可用闭环

同时实现歌曲、专辑和艺术家详情的最小完整内容，以及共享关系链接和返回恢复。从播放列表开始跑通第 1 节主线。艺术家落地页必须展示本地作品总览，不能继续自动把第一张专辑当成详情。

### C. 统一入口与资料职责

让搜索、quickplay、正在播放、上下文菜单使用同一导航接口；统一歌曲结果交互。旧 InfoPanel 收敛为资料管理入口，按实体种类显示字段和编辑范围。处理喜欢语义与默认列表显示名，保持既有数据兼容。

### D. 边界与验证

每个阶段做相关类型／行为验证，最终以真实桌面闭环验收。若进入 Rust 或持久化改动，补充该范围必要检查；不因为 UI 需要艺术家资料就扩大 Tauri 权限。

## 10. 验收场景

| 场景 | 必须成立 |
| --- | --- |
| 播放列表 → 歌曲 → 专辑 → 艺术家 → 另一专辑 → 返回 | 每个对象正确；选中、滚动、焦点恢复；队列与播放进度连续 |
| 搜索后进入多个对象再返回 | 查询、筛选、排序和结果定位保留 |
| quickplay／正在播放进入相同对象 | 内容和可用关系一致；返回来源正确 |
| 行主体、关系、喜欢与播放按钮交替操作 | 各动作独立；点关系不播放，双击不误冒泡；焦点始终可见 |
| 同名专辑、不同艺术家、双碟、合辑、多署名、同名艺术家 | 不错误合并；排序正确；无法可靠拆分时保留原始署名 |
| 只有单曲或部分本地曲目 | 数量诚实，不虚构完整专辑、完整作品目录或热门排名 |
| 缺图、缺简介、未知年份／时长、离线、元数据失败 | 主要浏览仍可用，没有假信息或挡住正文的空卡 |
| 打开资料后快速切换对象，再收到旧响应 | 不显示上一个对象的资料，不修改错误范围 |
| 浏览中重扫、编辑名称、移除文件／列表 | 精确对账或显示不可用，不能跳到第一项或清空其他状态 |
| 手动／智能／喜欢／当前队列 | 顺序和收录语义正确，详情浏览不重建播放队列 |
| 默认与最小窗口、长中英标题、长列表、减少动态效果 | 首屏层级清晰、正文不截断、控件可达；返回不重播长动效 |

正式前端实现需 `npm run build`、`npm test`，增加有意义的关系解析、导航恢复、异步对象隔离及实际点击行为测试。源码／CSS 守卫不能替代真实流程检查。本轮只完成设计与独立交互稿时，不将这些应用验收项标为已通过。
